## Input

```text
$ARGUMENTS
```

ID задачи обязателен. Нет — покажи таблицу задач текущего исполнителя со статусом `todo` и остановись.

## Шаги

1. Прочитай строку задачи в `docs/backlog.md`: формулировку, оценку, зависимости, критерии приёмки.
   Зависимость не `done` в `main` → скажи об этом и предложи работать на фикстуре или подождать.
2. Прочитай разделы `docs/plan.md`, относящиеся к задаче (движок §6, консилиум §7, UI §8, контракт §5),
   и `AGENTS.md` «Критические правила». Числа берутся из `docs/source/dataset.md`.
3. Проверь ветку: `git branch --show-current`. Амир → `feat/engine-consilium`, Мирас → `feat/ui`.
   Ты в `main` → остановись и предложи переключиться.
4. План из 3–6 шагов одним сообщением, затем реализация без лишних вопросов. Меняется `src/lib/types.ts`?
   Остановись: это отдельный PR в `main` с сообщением напарнику.
5. Ворота: `yarn tsc --noEmit`, `yarn test`. Красное — чини, пока не зелёное.
6. В `docs/backlog.md` поставь статус задачи `review` (колонку статуса добавить, если её нет).
7. Отчёт: что сделано, какие критерии приёмки закрыты, какие нет и почему. **Не коммить** — коммит только по
   явной просьбе.
