## Input

```text
$ARGUMENTS
```

Аргументы: ID задач и/или ветка. Пусто → текущая ветка против `main`.

> Ты оркестратор, не ревьюер. Аудит делегируй агенту `code-reviewer` с полным контекстом.

## Шаги

1. Scope: `git diff main...HEAD --stat`. Список файлов и ID задач (из аргументов, названия ветки, коммитов).
2. Делегируй `code-reviewer`: diff, файлы, ID задач, ссылки на `docs/plan.md` и `docs/backlog.md`.
   Для веток с `.tsx` дополнительно параллельно `ui-reviewer`.
3. Триаж: каждую critical/high и разумные medium — правка (сам, если тривиально, иначе профильный агент),
   повтор ворот, повтор ревью области. Не согласен с находкой — опровергни командой и выводом, не мнением.
4. Итог: `PASSED` только без открытых critical/high и с зелёными воротами. Иначе `CHANGES_REQUIRED` со списком.
5. Вывод пользователю: находки → как закрыты, вывод ворот, итог, «какие критерии приёмки НЕ покрыты?».
   Merge и коммит — только по явной просьбе.
